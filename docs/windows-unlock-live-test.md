# Windows 电脑操作：真机验收清单（给实测同事）

> Flowship 新版让 AI 能操作电脑上的任何应用，包括**电脑锁屏之后**。Windows 这一块在开发时**没有 Windows 机器可测**，代码是照系统文档和行为写的。请你在真机上把下面的项目过一遍，告诉我们哪些通、哪些不通。
> 设计和原理见 `docs/COMPUTER-USE.md`（不用读也能做这份清单）。
>
> 预计耗时：A 部分约 30 分钟（只点按钮、锁屏，不改系统）；B～E 部分约 1.5～2 小时（要装一个系统级小服务，需要管理员授权；C9-c 要干等 10 多分钟，可选）；F 部分（UAC / 安全桌面）约 20 分钟，装好之后做；G 部分（管道实例被占满）约 10 分钟，建议做。
> 每项标了优先级：**必测** / 建议 / 可选。时间不够就只做必测；**F 组里的必测项是安全底线，请务必做**。

## 0. 先读这个

**会碰什么**

- A 部分：只在 Flowship 里点按钮、锁屏，不改系统。
- B 部分起：会装一个**以系统身份运行的小服务**（需要管理员授权一次），并在本机保存一个开机密码，让 AI 能在锁屏界面自动解锁。随时能在设置里卸载，**卸载会把保存的密码一起删掉**。

**必须遵守**

1. 用**测试机 / 测试账户**，开机密码设成**不重要**的。不要用日常工作账户的真实密码；**不要在公司电脑上测**（账户锁定策略可能把账户锁掉）。
2. 这份清单里没有任何一步需要你把开机密码发给别人，请不要发。
3. 自动解锁**一次最多输一次密码**，失败后会冷却 10 分钟。别连着重试，先看原因。
4. 每个测试按钮的弹窗里会提示「期间不要碰键盘和鼠标」，请照做。
5. 每次测试前，把 Windows「睡眠」设成「从不」（设置 → 系统 → 电源），免得电脑中途睡着干扰结果。睡眠 / 息屏另有单独的项目（D5、D6）。

**立刻停手、马上反馈**

- 在任何地方（Flowship 界面、日志、诊断文件、审计文件、AI 的对话或截图里）看到了**开机密码明文**——这是最严重的缺陷；
- 账户被锁定；
- 电脑卡在黑屏 / 锁屏回不到桌面，而且不是密码输错；
- 卸载之后系统里还有 Flowship 的计划任务或 `FlowshipUnlockHelper.exe` 进程。

**万一遮罩没消失、鼠标键盘没反应**：按 `Ctrl+Alt+Del` → 任务管理器 → 结束 Flowship。遮罩随进程一起消失。

## A. 锁屏后台模式（不装任何东西）

> 这是 Windows 路线的前提：电脑**一直保持锁屏**，AI 对锁屏前**已经打开**的应用窗口发消息、逐窗口截图。它不能开新应用（不能用 Win 键 / Alt+Tab）。先确认这一档在你的机器上到底行不行。

**A0 打开开关（必测）**

- 做：打开「电脑操作」总开关，再打开「锁屏时也能用」。
- 预期：开关能打开（Windows 上**不会**要求先保存开机密码）；页面写着锁屏后台模式的说明；「解锁组件」那一行显示**未安装**。
- 不符合：截图 + 导出诊断信息（见第 7 节）。

**A1 摆好靶子应用（必测）**

打开并保持以下窗口（装了哪个开哪个）：记事本、计算器、文件资源管理器、Edge、Chrome、飞书或微信、VS Code。记事本里先不要输入内容。

**A2 点「测试后台操作」（必测）**

- 做：点按钮 → 确认 → 手离开键鼠。约 5 秒后电脑锁屏，等 30 秒左右，**自己解锁**，回到设置页看结果。
- 预期：「测试通过」，逐步清单里这几步都是 ✓：倒计时 → 打开测试窗口 → 锁屏 → 确认仍在锁屏 → 锁屏时截图 → 锁屏时输入。「锁屏时截图」那步的详情会列出其它应用各自的状态（画得出来 / 画不出来）。
- 记录：每一步的 ✓/✗、耗时和详情；各应用的状态。
- 说明：**这一项失败也很有价值**。如果「锁屏时截图」或「锁屏时输入」失败，说明后台模式在这台机器上整个不成立，请导出诊断信息一并发来。

**A3 真实任务：锁屏后让 AI 干活（必测）**

- 做：在 Flowship 里新开一个对话，发：「请在记事本里输入『Flowship 后台测试 123』，不要保存。」
- 怎么保证是「锁屏之后」才开始：
  - 有飞书：先锁屏（`Win+L`），再用手机飞书给 Flowship 发这句话；
  - 没有飞书：在 Flowship 里发「**先等我 30 秒，我要锁屏，30 秒后再开始**：请在记事本里输入……」，发出后立刻 `Win+L`。
- 等 1～2 分钟后自己解锁，回来看 AI 的执行记录和记事本。
- 预期：记事本里出现这句话；电脑**全程保持锁屏**（没被解锁、没有遮罩）。
- 记录：AI 每步的截图是否清晰、结果里有没有提示「某些窗口画不出来」、记事本最终内容、整个任务耗时。

**A4 各应用兼容性（必测）**

对每个应用各做一次最简单的操作（A3 的方式），记到下表：

| 应用 | 建议的操作 | 结果（✓可截图可操作 / 只能截图 / 画面是旧的 / 空白 / 操作无效） |
|---|---|---|
| 记事本 | 输入一句话 | |
| 计算器 | 点 `1` `+` `1` `=` | |
| 文件资源管理器 | 点进某个文件夹 | |
| Edge | 点页面里某个链接 | |
| Chrome | 点页面里某个链接 | |
| 飞书 / 微信 | 点某个会话（**别发消息**） | |
| VS Code | 在编辑器里输入一行 | |

预期（开发时的推测，不是保证）：经典 Win32 窗口（记事本 / 计算器 / 资源管理器）较可能可用；Chromium 和 Electron 系（Edge / Chrome / 飞书 / VS Code）锁屏时很可能画不出来或操作无效。**真实情况以你测到的为准**，这张表会直接决定后台模式的宣传口径。

**A5 锁屏期间用户回来（可选）**

- 做：AI 在锁屏下操作到一半，你自己解锁。
- 预期：这次会话因「电脑被解锁」而结束，Flowship 里能看到对应事件；之后 AI 再请求时按正常方式（没锁屏）重新开始。

**A6 管理员权限的窗口（可选）**

- 做：右键记事本 → 以管理员身份运行，在锁屏下让 AI 往里打字。
- 预期：被系统拦住，AI 收到「操作没成功」类的提示（Windows 不允许普通进程给管理员窗口发消息）。

**A7 点标题栏 / 菜单栏 / 边框（建议；第三轮评审补）**

> 后台模式发的是「客户区坐标」的鼠标消息，点在标题栏、菜单栏、边框（非客户区）上它处理不了——以前这种点击「成功返回、什么也没发生」，AI 会以为窗口已经最小化 / 关掉。现在代码改成明确拒绝。判断依据（没下钻到任何子控件、点又落在顶层窗口客户区原点的上方 / 左边）是照文档推的，**没在真机上验证过**。

- 做：和 A3 一样先锁屏再触发，让 AI：① 点记事本窗口右上角的「关闭」或「最小化」按钮；② 点记事本菜单栏里的「文件」；③ 从记事本的标题栏拖动窗口；④ 对照：点记事本中间的编辑区。
- 预期：①②③ AI 收到「这个位置是窗口的标题栏 / 菜单栏 / 边框，不是窗口内容区：锁屏后台模式点不到……」（错误码 `NEED_FOREGROUND`），**窗口没有被关掉 / 最小化 / 移动，菜单没有展开**；④ 照常有效。
- 记录：自绘标题栏的应用（Edge / Chrome / VS Code / 飞书——它们的标题栏本来就画在客户区里，**不在拒绝范围**）点标签栏 / 标题栏的结果（有效 / 无效 / 被拒）；窗口的右边框和下边框（代码读不到客户区大小，**没有检查**）点上去的结果。

**A8 窗口很多或很大时的内存（可选；第三轮评审补）**

- 做：打开约 30 个窗口（多开记事本 / 资源管理器），其中几个最大化；锁屏后让 AI 连续截几次图。同时开着任务管理器，盯 Flowship 主进程的内存。
- 预期：截图正常返回、不卡死；主进程内存**不会**因为窗口多 / 大而涨到几个 GB（设计上一帧里所有窗口位图合计不超过 256MB，另有合成和压缩的开销）；窗口多到超出预算时，AI 收到的截图说明里更下层的窗口状态是 `skipped`（多半本来就被盖住）。
- 记录：窗口数、屏幕分辨率与缩放、内存峰值、结果里 `skipped` 的个数、每次截图耗时。

## B. 安装解锁组件

> 后台模式画不出你要操作的应用时才需要它。它是一个以系统身份运行的小服务，AI 需要解锁时由它在锁屏界面输入你保存的开机密码。**默认不装、实验功能。**

**B1 安装（必测）**

- 做：点「安装解锁组件」→ 确认 → Windows 弹出管理员授权框（UAC）→ 点「是」。等一会儿（现场编译，可能 10～60 秒）。
- 预期：弹出「解锁组件已安装」，设置页显示**已安装**。UAC 框里的程序是 Windows PowerShell（不是 Flowship），这是正常的。
- 记录：耗时；UAC 框截图；有没有出现 SmartScreen / 杀毒软件的拦截或提示；失败时的完整错误文案（里面带退出码）。
- 失败时额外附上：`C:\ProgramData\Flowship\unlock\public\install.log`（里面没有密码，可以直接发）。

**B2 检查磁盘 / 权限 / 计划任务（必测）**

命令都是只读的，复制到 PowerShell 里跑（标了「管理员」的要用管理员身份打开 PowerShell）：

```powershell
# —— 管理员 PowerShell ——
icacls 'C:\ProgramData\Flowship\unlock'
icacls 'C:\ProgramData\Flowship\unlock\public'
icacls 'C:\Program Files\Flowship\unlock'
Get-ChildItem 'C:\ProgramData\Flowship\unlock' | Select-Object Name, Length, LastWriteTime
```

```powershell
# —— 普通 PowerShell（别用管理员）——
Get-ScheduledTask -TaskPath '\Flowship\' | Select-Object TaskName, State
(Get-ScheduledTask -TaskPath '\Flowship\' -TaskName 'Flowship Unlock Helper').Principal | Select-Object UserId, RunLevel, LogonType
Get-Process FlowshipUnlockHelper | Select-Object Id, SessionId
Get-Content 'C:\ProgramData\Flowship\unlock\public\pipe.txt'
Get-Content 'C:\ProgramData\Flowship\unlock\public\install.log'
Get-Content 'C:\ProgramData\Flowship\unlock\public\helper.log' -Tail 40
Get-ChildItem 'C:\ProgramData\Flowship\unlock'
```

| 检查 | 预期 |
|---|---|
| `…\unlock` 的 `icacls` | 只有 `NT AUTHORITY\SYSTEM` 和 `BUILTIN\Administrators`（完全控制）。**不能有** `Users` / `Everyone` / `Authenticated Users` |
| `…\unlock\public` 的 `icacls` | 比上一项多一行 `BUILTIN\Users`，只有读取和执行（`RX`） |
| `C:\Program Files\Flowship\unlock` 的 `icacls` | `Users` 只有读取和执行（`RX`），不能写 |
| `…\unlock` 里的文件（管理员） | 保存过开机密码后才有 `cred.bin`；`config.txt`（一行账户标识）；`state.txt` 在失败过之后才有；**不应有 `cred.bin.tmp`**（保存时的临时文件，保存成功后就没了；看到它说明某次保存中途失败过，记下来——下一次保存会覆盖它、点「清除」会一并删掉） |
| 计划任务 | `Flowship Unlock Helper`，状态 `Running`；运行身份 `SYSTEM`，`RunLevel` 为 `Highest` |
| `FlowshipUnlockHelper` 进程 | 在运行，`SessionId` 是 `0` |
| `pipe.txt` | 一行，形如 `FlowshipUnlock-` 加 32 位十六进制 |
| `install.log` | 中文，最后一行「安装完成」，没有任何密码 |
| 最后一条（**普通** PowerShell 列 `…\unlock`） | **拒绝访问**（普通用户不能看这个目录） |

- 记录：和预期不一样的任何一项，附上命令输出的文字（不是截图也行）。

**B2a 安装之后的几项加固痕迹（必测，30 秒）**

```powershell
# —— 管理员 PowerShell ——
Test-Path 'C:\ProgramData\Flowship\unlock\build'
# —— 普通 PowerShell ——
Select-String -Path 'C:\ProgramData\Flowship\unlock\public\helper.log' -Pattern 'selftest'
```

| 检查 | 预期 |
|---|---|
| `…\unlock\build` 是否存在 | `False`（编译用的私有临时目录，编完不管成败都会删；残留说明编译中途出过问题） |
| `helper.log` 里的 selftest | 有一行 `selftest：会话锁定状态读取结果=unlocked`（安装时你坐在桌面上，所以是 `unlocked`），随后一行 `selftest 通过`。读成 `unknown` 时安装本来就会失败（退出码 15，selftest 自己是 27）——**如果你真的遇到，请把整行日志发来，这是最重要的发现之一**（见下面 F 组） |

**B3 管道只允许登记的账户连（可选，要第二个本地账户）**

在**安装时登录的那个账户**的普通 PowerShell 里：

```powershell
$name = (Get-Content 'C:\ProgramData\Flowship\unlock\public\pipe.txt' -Raw).Trim()
$p = New-Object System.IO.Pipes.NamedPipeClientStream('.', $name, [System.IO.Pipes.PipeDirection]::InOut)
try { $p.Connect(3000); 'CONNECTED' } catch { $_.Exception.GetType().Name + ': ' + $_.Exception.Message } finally { $p.Dispose() }
```

- 预期：输出 `CONNECTED`（连上后什么都不发就关掉，组件不会有任何动作）。
- 切到**另一个**普通本地账户（快速用户切换）跑同一段：预期是 `UnauthorizedAccessException`（拒绝访问）。

**B4 保存开机密码（必测）**

- 做：「开机密码」→ 保存 → 输入**测试账户**的密码 → 保存。
- 预期：显示「开机密码：已保存」。
- 再试一次：保存一个含中文的密码（比如 `密码123`）→ 预期**被拒绝**，提示目前只支持英文字母、数字和常见符号，并且没有保存。
- 检查（管理员 PowerShell）：`…\unlock\cred.bin` 存在，用记事本打开是乱码（没有明文）；`helper.log` 里有「已保存开机密码（长度不记录）」。

**B5 提权链的「假模块」劫持（可选，进阶；验证安装脚本对 `PSModulePath` 的加固是否在 Windows PowerShell 5.1 上起作用）**

背景：PowerShell 按需自动加载模块，而默认模块搜索路径里有你自己 `Documents\WindowsPowerShell\Modules` 这个用户可写的目录。如果有同名假模块，管理员身份的安装脚本可能替它执行代码。安装的「引导」在最开始就把模块路径钉成 PowerShell 自带的目录。**这一项在真机上能证明钉死确实管用，也能证明没有把安装弄坏**。

先**卸载**解锁组件，然后在**普通 PowerShell**里造一个假的 `ScheduledTasks` 模块（它只往一个标记文件里写一行字，不做任何别的事）：

```powershell
$dir = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'WindowsPowerShell\Modules\ScheduledTasks'
New-Item -ItemType Directory -Force $dir | Out-Null
@'
function Get-ScheduledTask { Add-Content 'C:\Users\Public\flowship-hijack-marker.txt' ("hijacked by fake module, user=" + [Environment]::UserName + ", elevated=" + ([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole('Administrators')); return $null }
Export-ModuleMember -Function Get-ScheduledTask
'@ | Set-Content (Join-Path $dir 'ScheduledTasks.psm1')
Remove-Item 'C:\Users\Public\flowship-hijack-marker.txt' -ErrorAction SilentlyContinue
```

- 做：在 Flowship 里点「安装解锁组件」→ UAC 点「是」→ 等安装结束。
- 预期：**安装成功**（设置页显示已安装），而且 `Test-Path 'C:\Users\Public\flowship-hijack-marker.txt'` 是 **`False`**（假模块没被加载）。
- 如果标记文件出现了：打开看内容（`elevated=True` 说明管理员身份的脚本真的加载了你的假模块——**钉死没生效，请马上告诉我们**）。
- **一定要清理**：`Remove-Item -Recurse -Force (Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'WindowsPowerShell\Modules\ScheduledTasks')`，再 `Remove-Item 'C:\Users\Public\flowship-hijack-marker.txt' -ErrorAction SilentlyContinue`。
- 如果安装失败了：附上 `install.log` 和失败提示里的退出码——失败而没有标记文件，说明钉死后某个命令找不到模块（也是要我们知道的问题）。

## C. 自动解锁实测

> **有风险**：输错一次会进入冷却，且在系统的登录失败记录里留一次失败。先确认下面的前置条件。

**前置条件（必须）**：测试账户的锁屏界面**直接显示密码框**，而不是 PIN。检查：`Win+L` → 按任意键 → 看是不是密码输入框（没有「PIN」字样）。如果是 PIN：设置 → 账户 → 登录选项 → 删除 PIN（或关掉「仅允许对此设备上的 Microsoft 帐户使用 Windows Hello 登录」），让默认登录方式变成密码。

**C1 点「测试自动解锁」（必测）**

- 做：点按钮 → 确认 → 手离开键鼠。约 5 秒后锁屏，Flowship 自动解锁并回到桌面，回到设置页看结果。
- 预期：「测试通过」，逐步清单每一步都是 ✓。解锁过程通常十几秒内完成。
- 记录：总耗时；你肉眼看到的过程（锁屏界面有没有出现密码框、有没有一闪而过用户桌面）；失败时的完整提示文案。

**C2 真实任务：AI 自动解锁后操作，再锁回去（必测）**

- 做：和 A3 一样锁屏后触发，但让 AI 走前台：「请在记事本里输入『Flowship 解锁测试』，不要保存。**如果后台模式不行，就解锁电脑后再操作**。」
- 预期（逐条看，不一致都记下来）：
  - [ ] AI 先试后台模式；需要时自动解锁；
  - [ ] **遮罩**盖住了所有显示器，旁人看不到屏幕内容；
  - [ ] AI 的点击和输入**有效**（遮罩没有吞掉点击）；
  - [ ] AI 的截图是真实屏幕，**不是纯黑 / 纯遮罩色**；
  - [ ] 你中途动一下鼠标 → AI 让位（遮罩消失、AI 停手），而不是继续抢鼠标；
  - [ ] 任务结束后电脑**自动重新锁屏**。
- 记录：任何一条不符合的现象；导出诊断信息（里面有「遮罩会不会被截进画面」的判断结果）。

**C3 Caps Lock 开着（必测）**

- 做：锁屏前按一下 Caps Lock（键盘灯亮）→ 重做 C1。
- 预期：解锁成功（组件会先把 Caps Lock 关掉再输入）。解锁之后 Caps Lock 是**关**的（这是它的副作用，记下来即可）。
- 说明：**这条在开发时没法验证**，是已知风险。如果失败，提示会说「提交密码后电脑仍然是锁屏状态…」，之后进入冷却，请记录，再按下面的「清冷却」继续测。
- **清冷却**：设置里重新「保存开机密码」（再输一次同一个密码）即可立刻解除冷却。

**C4 含符号的密码（建议）**

- 做：把测试账户的密码改成 `Aa1!@#$%^&*()-_=+` 这类含大小写、数字、需要 Shift 的符号和不需要 Shift 的符号的密码，在 Flowship 里重新保存，再做 C1。再换一个含 `\ | " ' ` ~ [ ] { } ; : , . < > / ?` 的密码各试一次。
- 预期：都能解锁。
- 记录：哪个字符会失败（失败的密码里逐个字符排查是哪一个）。

**C5 PIN 为默认登录方式（负面测试，必测）**

- 做：把默认登录方式改回 PIN → 保存开机密码 → C1。
- 预期：测试**失败**，提示里提到「锁屏界面默认的登录方式是 PIN / 指纹 / 人脸…」；**之后马上再点一次 C1**，应该被冷却拒绝（提示「刚刚自动解锁失败过…约 N 分钟后恢复；重新保存开机密码可立即恢复」）。需要你自己解锁。
- 说明：这是预期内的不支持场景，要确认的是「失败得干净」——只输了一次、冷却生效、提示说得清楚。

**C6 保存了错误的密码（负面测试，必测）**

- 做：故意保存一个**错误**的密码 → C1。
- 预期：测试失败；**只输了一次**——锁屏界面最多出现一次「密码不正确」；`helper.log` 里这次只有一条「开始解锁」；再点 C1 立刻被冷却拒绝；账户**没有**被锁定。
- 检查：`helper.log`（普通 PowerShell 就能读）末尾若干行；管理员 PowerShell 看 `…\unlock\state.txt` 是否存在。

**C7 组件进程被结束（建议）**

- 做：任务管理器 → 详细信息 → 结束 `FlowshipUnlockHelper.exe`。观察 1～2 分钟。
- 预期：计划任务把它拉起来，`pipe.txt` 里的管道名变了；之后 C1 仍然成功。
- 说明：手动结束进程算不算「任务失败」、会不会触发自动重启，取决于系统。**拉不起来也如实记录**（不一定是缺陷），设置页会提示重新安装。

**C8 重启电脑（建议）**

- 做：重启，登录后看设置页。
- 预期：设置页显示**已安装**，`pipe.txt` 里的管道名和重启前不同，C1 成功。

**C9 冷却状态文件读不了 / 删不掉（建议；第三轮评审补）**

> 背景：冷却记在组件内存和 `state.txt` 里，取两者中更晚的。第三轮评审指出两个漏洞并已改：① 状态文件**一直读不了**（被杀毒软件占着）时，冷却曾恒回「整段 10 分钟」——永远倒不完，重新保存密码也没用；② 保存开机密码时冷却**清不掉**，组件仍回「已保存」，用户以为自动解锁已恢复，下一次请求却被冷却挡住。现在：读不了 → 从文件修改时间起算、会倒计时；删不掉 → 改写成「已清除」标记（内容 `0`）；连改写也不行 → 回 `COOLDOWN_NOT_CLEARED`。**这套逻辑已在 macOS 上用 PowerShell 7 / .NET 以 POSIX 文件权限真跑过**，但 NTFS 的共享冲突和 POSIX 的权限位不是一回事，这一项就是要在真 NTFS 上确认。
> **注意有两层冷却**：Flowship 主程序自己也记了一份（落在 `%APPDATA%\fe-ai-flow\desktop-state\` 下），而且设置页的「测试自动解锁」在锁屏**之前**就按它拦；组件里的 `state.txt` 是第二层。所以只要主程序那层还在冷却，C1 看到的拒绝来自主程序、碰不到组件的冷却逻辑——下面三个场景是这样设计的：① 靠「重新保存开机密码」（它会同时清两层）验证组件**清冷却**的两条退路；② 靠「等满 10 分钟」让主程序那层先过期，验证组件**读不了状态文件时会倒计时**。
> 前置：已安装解锁组件、已保存开机密码。要用到管理员 PowerShell。**这一项里自动解锁会故意失败几次（进冷却），做完请确认能重新解锁。每个场景开头都要重新让冷却生效：按 C6 的做法故意保存一个错误密码 → 点 C1（失败）；确认管理员 PowerShell 里 `Test-Path 'C:\ProgramData\Flowship\unlock\state.txt'` 是 `True`。**

- **C9-a 删不掉但改得了（建议）**
  - 做：冷却生效后，管理员 PowerShell 里打开状态文件，**允许别人读写、不允许删除**（模拟被占着；**保持这个窗口别关**），然后在 Flowship 里**重新保存正确的开机密码**，随后点 C1：

    ```powershell
    # —— 管理员 PowerShell ——
    $f = [System.IO.File]::Open('C:\ProgramData\Flowship\unlock\state.txt', 'Open', 'Read', 'ReadWrite')
    ```

  - 预期：保存**成功**（组件删不掉文件，就把它改写成已清除标记 `0`）；C1 **立刻成功**（不再被冷却挡）；`Get-Content 'C:\ProgramData\Flowship\unlock\state.txt'` 看到内容是 `0`；`helper.log` 里有一条「清冷却状态失败（删除）」。做完 `$f.Close()`。
- **C9-b 连改也改不了（建议）**
  - 做：冷却生效后，**独占**打开状态文件（`'None'`：别人读写删都不行），然后在 Flowship 里**重新保存正确的开机密码**：

    ```powershell
    # —— 管理员 PowerShell ——
    $f = [System.IO.File]::Open('C:\ProgramData\Flowship\unlock\state.txt', 'Open', 'Read', 'None')
    ```

  - 预期：设置页**不是**普通的「已保存」，而是「开机密码已经保存好了，但上一次自动解锁失败留下的冷却记录没能清掉……约 N 分钟后恢复；也可以稍后再点一次「保存」」（`COOLDOWN_NOT_CLEARED`）；点 C1 仍被冷却拒绝（主程序那层没清）；`helper.log` 里「清冷却状态失败（删除）」和「清冷却状态失败（改写成已清除标记）」各一条。然后 `$f.Close()`、再重新保存一次正确的开机密码 → 这回应是普通的成功，C1 成功。
- **C9-c 读不了时会倒计时（可选，要等 10 多分钟）**
  - 做：冷却生效后**马上**独占打开状态文件（同 C9-b 的命令，**保持窗口别关**），记下时间；**等满 10 分钟再多等 1～2 分钟**（让主程序那层冷却先过期），然后点 C1。
  - 预期：C1 **成功**（组件读不了状态文件时，从文件修改时间起算冷却，那个时刻 + 10 分钟已过，所以放行）。旧写法是「读不了就恒当作整段冷却」——这里会一直失败、永远倒不完。`helper.log` 里「读冷却状态失败，按「从最后修改时间起算」处理」只出现**一次**（不刷屏）；解锁成功后组件想清冷却也清不掉，会多出「清冷却状态失败（…）」两条，这是正常的。做完 `$f.Close()`。
- **C9-d 状态文件被写成远未来的时刻（可选，要等 10 多分钟；第四轮评审补）**
  - 背景：状态文件被改过、或系统时钟被往回拨过，组件会读到一个远在未来的截止时刻。旧写法是「超过一整段就回一整段」（封顶），**每次读都回满格**，冷却永远结束不了；现在第一次读到时就把它**夹成「那一刻 + 一整段」并固定下来**，之后照常倒计时、照常结束。这一条已在 macOS 上用 pwsh / .NET 把真实的 `Cooldown` 类跑过（窗口缩成 2 秒），真机上要确认的是整条链路。
  - 做：冷却生效后（按 C6 的做法故意失败一次），**让 Flowship 设置页留在前台**（它大约每 3 秒问一次组件状态，组件第一次被问到的那一刻就是夹紧的起点），管理员 PowerShell 里把状态文件改成一年后的时刻，记下时间：

    ```powershell
    # —— 管理员 PowerShell ——
    [System.IO.File]::WriteAllText('C:\ProgramData\Flowship\unlock\state.txt', [DateTime]::UtcNow.AddYears(1).Ticks.ToString())
    ```

    设置页保持 10 秒以上，然后**等满 10 分钟再多等 1～2 分钟**（让主程序那层冷却先过期），再点 C1。
  - 预期：C1 **成功**（组件把那个远未来的值夹成「第一次被问到的那一刻 + 10 分钟」，现在已过）。旧写法下这里会一直被组件的冷却挡住（回 `COOLDOWN`），永远倒不完。
  - 别和 C9-c 混着做（那里状态文件是读不了，这里是读得了、值很大）。
  - 另一处只在 macOS 上用 pwsh 验证过、**没有对应的真机场景**：状态文件在、但所在目录没有权限时，旧写法用 `File.Exists` 判断会得到 `false`（它吞掉权限错误），被当成「没有冷却」、`Clear()` 也会谎报「已清掉」；现在直接读 / 直接删，只有「文件 / 目录不存在」才算不存在。这种情况在 NTFS 上不容易人为造出来，所以没单独设场景。
- 记录：每个场景是否符合预期；`helper.log` 里上面那几行各出现几次。
- 不符合：把现象、`helper.log` 末尾 60 行、`state.txt` 的内容与 `(Get-Item 'C:\ProgramData\Flowship\unlock\state.txt').LastWriteTimeUtc` 发来。

## D. 边界场景

**D1 多显示器（建议，有多个显示器才做）**：遮罩是否盖住**所有**显示器；后台模式的截图只含主屏（记下来即可）；C2 里 AI 点击位置是否准确。

**D2 缩放比例（建议）**：把主屏缩放改成 125% / 150%，各做一次 C2 或 A4 的计算器：AI 点的位置和截图是否对得上。记下缩放比例和点偏了多少。

**D3 远程桌面（可选，影响较大，放最后做）**：用另一台电脑远程桌面登录测试机，在远程会话里运行 Flowship，点「测试自动解锁」。预期：失败并提示「Flowship 不在本机屏幕前的桌面会话里（比如正通过远程桌面使用）…」。做完回到本机重新登录。

**D4 快速用户切换（可选）**：另一个账户登录后（原账户保持登录），在它里面运行 Flowship 点「测试自动解锁」。预期：失败并提示「解锁组件只接受安装时登记的那个 Windows 账户…」。

**D5 睡眠 / 合盖（可选）**：让电脑睡眠（开始菜单 → 睡眠），再触发任务。**不期望成功**，只记录现象：AI 收到什么错误、电脑有没有被唤醒。

**D6 息屏 / 屏保后触发（必测）**：设置里让显示器 1 分钟后关闭，且唤醒时需要登录。等到屏幕黑了再触发任务（有飞书用飞书，没有就发「先等我 90 秒」的消息）。预期：能把屏幕叫醒、解锁、完成任务。——**这条最贴近真实场景**：人离开工位后屏幕通常已经息屏。记录屏幕有没有亮起来、是否解锁成功、耗时。

**D7 账户类型（建议，条件允许才做）**：本地账户和微软账户各做一遍 B + C1。记录账户类型和默认登录方式。

**D8 杀毒软件（建议）**：装了第三方杀毒软件（或只有 Windows Defender）的机器上做 B1。记录：有没有拦截 / 弹窗 / 隔离；Windows 安全中心 → 保护历史记录里有没有关于 `FlowshipUnlockHelper.exe` 或 PowerShell 的条目。不需要想办法绕过，只要如实记录。

**D9 公司策略（可选）**：如果 B1 失败且提示「策略把 PowerShell 限制成了受限模式」，记录这条和机器类型（公司电脑 / 个人电脑）。

**D10 输密码途中被打断（可选，很难踩点；第三轮评审补）**

> 背景：组件输完密码会等 80ms，然后在按回车**之前**再确认一次「输入桌面不是 Default、会话仍是已锁定」，不是就不按回车（输密码要几秒，这期间你可能自己用指纹 / PIN 解开了电脑，或者弹出了 UAC，回车会落进你当前的窗口 / 默认点「是」）。判据是照文档写的，**没在真机上验证过**。
> 前置：测试账户有指纹 / PIN 之类**另一种**解锁方式；把测试账户的密码设成很长的（组件每个字符约 50ms，60 位约 3 秒、100 位约 5 秒；Windows 本地账户密码最长 127 位，越长越好踩），在 Flowship 里重新保存。

- 做：点 C1「测试自动解锁」，电脑锁屏后盯着锁屏界面——密码框里的圆点开始一个个冒出来的那几秒里，用指纹 / PIN 把电脑自己解开。能踩中就踩，踩不中就换个时机多试几次（**每次失败都会进冷却**，用「重新保存开机密码」解除）。
- 预期：**不会按回车**，不会替你提交任何东西；`helper.log` 里是下面三种之一（取决于你在哪一刻解开）：「输入中途失败（错误码 …）」（输入桌面变了以后 `SendInput` 直接失败）/「提交前输入桌面已经是 Default（用户可能自己解锁了），不按回车」/「提交前读不到输入桌面，不按回车」；组件按「输过」收场、进冷却。落进你桌面窗口的字符：**不应该有**——有的话如实记下来，这才是这一项真正想知道的。
- 记录：是否踩中；`helper.log` 里 typist 那几行（是上面哪一种、错误码是什么）；有没有字符落进了你的窗口、落了几个。

**D11 前台会话进行中电脑被锁屏（建议；第三轮评审补）**

> 背景：前台会话的看门狗每 0.3 秒读一次锁屏状态，读到明确的「已锁定」就**结束会话**（原因 `relocked_externally`，不再锁、不再抢）；以前只有下一个动作开始时才看一眼，而 `desktop_type` 要打约两秒，期间被锁屏的话，剩下的字和回车会落进锁屏界面的密码框，等于一次错误登录。读不出锁屏状态按「不知道」处理、不结束。这个结束原因**没有对应的用户可见提示**（设置页 / 飞书里都不会出现专门的文字），要看审计文件。
> 前置：做 C2 的流程，AI 在自动解锁之后的前台档里操作；要长一点的输入任务，比如「在记事本里输入一段 200 字的文字」。

- 做：
  1. **最简单**：AI 连续输入的过程中，自己按 `Win+L` 锁屏。
  2. **更严格（可选）**：想要「不经键鼠的锁屏」——`Win+L` 本身就是键盘输入，会话多半先按「用户接管」收场，碰不到这条逻辑。办法：先在另一个命令提示符里敲 `timeout /t 40 /nobreak > nul & rundll32.exe user32.dll,LockWorkStation` 回车，再让 AI 开始那个输入任务，然后**手拿开**，等约 40 秒后系统自己锁屏。
- 预期：
  - [ ] 会话结束、遮罩消失、AI 的输入停下；步骤 1 多半以「用户接管」（`user_took_over`）结束，也算通过；步骤 2 应以 `relocked_externally` 结束，从锁屏到停手不超过一两秒（看 `%APPDATA%\fe-ai-flow\desktop-audit\<日期>.jsonl` 里 `session_ended` 那一行的 `reason`）；

## F. UAC / 安全桌面（安全底线，必测）

> **这一组验证一条底线：屏幕上是 UAC 权限确认（或别的系统安全弹窗）时，AI 和解锁组件绝不会往里输入任何东西。**
> 为什么要测：UAC 和锁屏界面都画在 Windows 的「安全桌面」上，程序很难一眼分清。如果把 UAC 当成锁屏去「解锁」，会把开机密码连同回车打进 UAC——而 UAC 里回车默认落在「是」，等于替你点了同意。Flowship 靠 Windows 的「会话锁定标志」把两者分开：会话**明确是已锁定**才会输入，**读不出来也不输入**。这个标志的结构和语义是照文档写的，**开发时没有任何一台 Windows 验证过**，请你替我们确认。
> 前置：已安装解锁组件（B1）、电脑操作总开关和「锁屏时也能用」都开着。用测试机 / 测试账户。要能随时弹出 UAC：下面统一用 `Start-Process notepad -Verb RunAs`（管理员账户会弹「是 / 否」框；标准用户账户会要求输入管理员密码——后者别输，直接取消）。

**F1 识别出 UAC（必测）**

- 做：
  1. 在 Flowship 里新开一个对话，发：「**先等 60 秒，然后调用 desktop_status，把返回里「电脑：」那一行原样告诉我**。」
  2. 立刻在普通 PowerShell 里运行 `Start-Process notepad -Verb RunAs`，UAC 弹出后**先别点**，手离开键鼠。
  3. 等 60 秒左右（AI 在这期间调了 `desktop_status`），再在 UAC 里点「否」，回到对话看 AI 的回复。
- 预期：AI 转述的那一行是「**屏幕上现在是系统安全提示（如 UAC 权限确认），不是锁屏**；这只能由用户本人处理，现在开始操作会被拒绝……」。**不是**「现在是锁屏状态」，也不是「没有锁屏」。UAC 全程没有被点过（是你最后点的「否」）。
- 对照：UAC 关掉后再问一次同样的话 → 那一行是「没有锁屏」。再让电脑真的锁屏（`Win+L`）、用飞书发同样的话 → 那一行是「现在是锁屏状态」。**三种状态要能分清。**
- 不符合：把 AI 的原话和 `helper.log` 最后 40 行发来；再用 F6 的办法导出诊断，一起发来。

**F2 UAC 弹着时 AI 想操作（必测）**

- 做：和 F1 一样，只是让 AI 在 60 秒后调用 **`desktop_screenshot`** 并把结果原样告诉你（把第 1 步的话改成「先等 60 秒，然后调用 desktop_screenshot，把返回原样告诉我」）。
- 预期：AI 的回复是**被拒绝**——「电脑屏幕上正显示 Windows 的系统安全提示（比如 UAC……）……不要重试」（错误码 `SECURE_DESKTOP`）。同时：UAC 没有被碰过；屏幕上**没有出现**遮罩；`helper.log` 里**没有**新的「开始解锁」记录；`%APPDATA%\fe-ai-flow\desktop-audit\<日期>.jsonl` 里这次没有 click / type / key 之类的动作。
- 记录：AI 的原话；审计文件里这一段的内容（只有动作名和长度，没有输入内容）。

**F3 AI 操作进行中弹出 UAC（必测，最贴近真实场景）**

- 做：在 Flowship 里发：「**打开开始菜单，搜索「记事本」，在搜索结果里点右侧的「以管理员身份运行」**。」（需要电脑没锁屏时做。）UAC 会在 AI 点击之后弹出，AI 紧接着的自动截图会撞上它。
- 预期（UAC 弹出的瞬间可能赶在、也可能赶不上那张自动截图，所以「被拒绝」可能出现在点击这一步的结果里，也可能出现在 AI 紧接着的下一步里，两种都算对）：
  - [ ] AI 拿到的是「屏幕上正显示系统安全提示（UAC）……不要重试」这类拒绝（错误码 `SECURE_DESKTOP`），转告你「需要你亲自处理」，**AI 没有替你点「是」**；
  - [ ] Flowship 任务事件流里有一条「屏幕上弹出了需要你亲自处理的系统安全提示（如 UAC 权限确认）……」；
  - [ ] 如果接了飞书：飞书里收到同样的提醒；
  - [ ] **电脑没有被锁回去**（你就在电脑前要处理弹窗，不会锁屏）；
  - [ ] 你自己处理（点「是 / 否」）之后，再让 AI 继续（重新截图即可）——**不会**被冷却拒绝。
- 记录：以上逐条是否成立；弹窗出现到 AI 停手的大致时间。
- 提醒：这一项里 UAC 是**你**点的。AI 如果在 UAC 上点了任何东西，立刻记录并告诉我们——那是最严重的一类问题。

**F4 锁屏界面依然能解锁（回归，必测）**

- 做：这组加固加了新的拒绝条件，要确认它**没有误伤正常的锁屏解锁**：重做 C1（点「测试自动解锁」），再做一次 C2。
- 预期：和加固前一样**成功**。
- 如果失败：看 `helper.log` 里 typist 那几行。出现下面任一句说明新判据和这台机器对不上，**请原样发来**（这是我们最想知道的）：
  - `读不出会话是否锁定（…），为安全起见不输入`——括号里是原因：`Level=N`、`结构里的会话号 N 和本进程的 M 对不上` 说明系统返回的数据布局和我们的假设不符；`SessionFlags=N` 说明标志取值不在 0 / 1 之内；还可能是查询本身失败；
  - `会话没有锁定，输入桌面却是 Winlogon：这是 UAC 权限确认之类的安全提示，不输入`（而你当时明明是锁屏——说明「锁定 / 未锁定」的标志值和我们的理解相反）。

**F5 `Ctrl+Alt+Del` 界面（可选，只记录现象）**：按 `Ctrl+Alt+Del` 出现安全界面（锁定 / 切换用户 / 任务管理器……）后**不要点任何东西**，重复 F1 的第 1 步（先等 60 秒再看状态），60 秒后按 `Esc` 回到桌面。记录 `secureDesktop` 是 `true` 还是 `false`（开发时没有把握，记下来即可）。**绝对不要在这个界面上点「锁定」。**

**F6 导出诊断信息里的锁定标志（建议）**：电脑在**普通桌面**时导出诊断信息，打开 JSON 看 `driver.sessionLock`（预期 `"unlocked"`）和 `driver.inputDesktop`（预期是 `Default`）。这两项是你判断「标志读得对不对」最直接的依据。（`driver.inputDesktop` 能读出 `Default` 还顺便证明了：打开输入桌面用的访问掩码在真机上够用——第三轮评审后从只申请「切换桌面」改成「读对象 + 切换桌面」两项（`0x101`），因为只申请前者时能不能读出桌面名没人在真机上验证过；这里是 `null` / 空就说明读桌面名这一步没读出来，整个功能会退化成「锁屏状态未知」，立刻告诉我。）

## G. 管道实例被占满时服务不退出（建议；第二轮评审补，开发时没在 Windows 上跑过）

> 验证一个**可用性**假设：登记账户下的进程把组件的管道实例（最多 8 个）占满之后，服务**不会退出**，占用一释放就自己恢复。以前的写法是「接受不到客户端连续失败 20 次就退出」，而计划任务只会在崩溃后重启 5 次——同账户下的进程占着不放，服务就会永久停摆。现在运行阶段不再因此退出，只丢掉坏实例、退避重试、限频记日志。
> 这是**同账户下的进程**造成的可用性问题，不涉及开机密码（占着实例的进程读不到密码、也解不了锁）。前置：已安装解锁组件（B1）。用测试机 / 测试账户。**占用期间不要点「测试自动解锁」**（它会先锁屏，而此时组件连不上，锁了屏回不来要你自己手动解锁）。

**G1 占满实例，服务仍在，释放后自动恢复（建议）**

- 做：
  1. 普通 PowerShell（**登记的那个账户**，别用管理员）里先记下服务进程和日志行数：

     ```powershell
     Get-Process FlowshipUnlockHelper | Select-Object Id, StartTime
     (Get-Content 'C:\ProgramData\Flowship\unlock\public\helper.log').Count
     Get-Content 'C:\ProgramData\Flowship\unlock\public\pipe.txt'
     ```

  2. 同一个 PowerShell 里运行下面这段，把管道实例占满（组件对每个连接最多保留 90 秒，所以请在 90 秒内做完第 3 步）：

     ```powershell
     $name = (Get-Content 'C:\ProgramData\Flowship\unlock\public\pipe.txt' -Raw).Trim()
     $held = @()
     for ($i = 1; $i -le 10; $i++) {
       try {
         $c = New-Object System.IO.Pipes.NamedPipeClientStream('.', $name, [System.IO.Pipes.PipeDirection]::InOut)
         $c.Connect(2000)
         $held += $c
       } catch {
         "第 $i 个没连上：$($_.Exception.GetType().Name)"
       }
     }
     "已连上 $($held.Count) 个"
     ```

  3. 占用期间看 Flowship 设置页「解锁组件」那一行（它大约每 3 秒刷新一次状态）：记下它显示什么。**不要点任何测试按钮。**
  4. 等 90 秒左右连接被组件关掉（或手动释放：`$held | ForEach-Object { $_.Dispose() }`），再等约 10 秒。
  5. 重新运行第 1 步的三条命令，和占用前对比。
- 预期：
  - [ ] 第 2 步：连上 **8 个**左右，之后的连接报超时（`TimeoutException`）；
  - [ ] 占用期间设置页的组件状态变成「连不上 / 没有在运行」一类（原文记下来），**释放后约 10 秒内自己恢复成正常的「已安装」**，不需要重装、不需要重启 Flowship；
  - [ ] 占用前后 `Get-Process` 的 `Id` 和 `StartTime` **完全一样**（服务没有退出、没有被计划任务重启过）；`pipe.txt` 里的管道名也**一样**；
  - [ ] `helper.log` 只多了**寥寥几行**（大约 4 条以内）「接受连接 / 创建管道出错（连续第 N 次）：…」，**没有** `fatal`、没有新的「service 启动」，也没有刷屏（几十 / 上百条）；
  - [ ] 释放之后做一次 C1（点「测试自动解锁」）仍然**成功**。
- 记录：以上逐条是否成立；占用期间设置页的原文；`helper.log` 新增的那几行（没有密码，可以直接贴）。
- 如果服务退出了（`Get-Process` 找不到、或 `Id` 变了）：把 `helper.log` 最后 60 行和 `Get-ScheduledTask -TaskPath '\Flowship\' | Get-ScheduledTaskInfo` 的输出发来——这说明「运行阶段不退出」的假设不成立。

| 解锁组件读不出会话是否锁定 / helper.log 里有「读不出会话是否锁定」 | 这台机器上读不到 Windows 的会话锁定标志，组件**宁可不输入也不乱输入**，所以解锁永远不会成功 | 把 `helper.log` 对应行和诊断信息发给我们（见 F4）；这是要我们改代码的问题 |
| 安装失败，提示里带「退出码 N」 | 见 `docs/COMPUTER-USE.md` 的退出码表（15 = 自检里读不出会话锁定状态） | 附上 `install.log` |
